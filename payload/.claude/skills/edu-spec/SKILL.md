# 기능 명세

대상은 $ARGUMENTS의 번호나 이름이다. 모호하면 진행 중인 기능을 보여주고 선택받는다.

1. contract, 해당 roadmap 항목과 연결 backlog만 읽는다. 목적과 MVP가 미확정이면 edu-interview로 연결한다. .claude/edu-templates/spec.md를 참고한다.
2. 기존 spec이 있으면 이어 쓴다. 기대 동작을 바꾸는 요청은 edu-change, 명세와 다른 실제 동작은 edu-fix로 연결한다.
3. .edu/specs/번호/spec.md에 목적·포함 범위·현재 제외 범위·사용자 동작·완료 조건을 적는다. 완료 조건에는 AC-01 같은 안정된 번호를 붙인다.
4. SPEC-001은 인터뷰에서 확정한 MVP 동작을 모두 포함한다. HTML 편집기 예제를 선택했다면 합의한 8개 동작을 포함하고 슬라이드 구분·텍스트 선택 규칙을 명시한다. 특정 샘플이나 파일명에만 동작하도록 범위를 몰래 좁히지 않는다. 지원 밖 입력의 처리 범위는 과장하지 않는다.
5. 후속 spec은 현재 기능만 상세화한다. 화면·데이터를 공유하는 기존 기능과 연결을 적는다. 오류·예외는 목적 달성을 막는 것과 중요한 회귀 조건을 우선한다.
6. 읽기 쉬운 초안을 보여준다. 사용자가 확정하면 status=specified로 기록한다. 작성·확정·검증을 같은 것으로 취급하지 않는다.
7. 다음은 edu-mockup이다. 새 화면이나 표시 변경이 없으면 spec에 목업 생략 이유를 적고 edu-plan으로 연결한다.
