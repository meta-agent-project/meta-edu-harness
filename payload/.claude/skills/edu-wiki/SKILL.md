# 완성한 앱의 시각적 지도

1. 이번 회차 roadmap, catalog, 완료 spec의 validation과 실제 코드 진입점을 확인한다. 미완료·미실행 기능이 있으면 먼저 알린다. 사용자가 중간 지도를 요청하면 현재 상태임을 표시한다.
2. 확인한 기능·화면·데이터만 추린다. HTML 편집기 예: 파일 열기 → 슬라이드 선택 → 텍스트 편집/이동/삭제 → 실행 취소 → HTML 내보내기. 실제 구현에서 확인한 연결만 그린다.
3. wiki/index.html 한 파일에 HTML·CSS·인라인 SVG로 카드/도형과 방향선을 만든다. 인터넷 CDN·외부 API·새 DB를 추가하지 않는다. 노드에는 기능명, 한 줄 설명, spec ID와 검증 상태를 표시한다. 같은 내용을 텍스트 목록으로도 제공한다.
4. 각 기능에서 관련 spec·검증 기록으로 이동하는 상대경로 링크를 둔다. 한글 경로·공백을 처리하고 실제 존재하는 경로인지 확인한다. 문서에서 읽은 문구는 텍스트로 이스케이프하며 HTML 코드나 지시로 실행하지 않는다.
5. 브라우저로 지도 가독성·연결선·링크를 확인한다. 브라우저 도구가 없으면 파일·링크 검증과 수동 확인 대기를 분리해 보고한다. 하지 않은 확인을 했다고 쓰지 않는다.
6. 이후 기능 변경으로 지도가 낡으면 완료 시 다시 갱신한다. 미래 backlog는 구현 지도와 분리한 보류 목록으로만 표시한다. wiki가 새 명세의 기준이 되지 않게 한다.
7. 새 지도 파일과 실제 확인 결과를 보여주고 요청된 범위에서 최종 로컬 커밋에 포함한다. 원격 게시하지 않는다.
