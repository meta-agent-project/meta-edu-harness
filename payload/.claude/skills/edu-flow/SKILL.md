# 진행 안내

인자 $ARGUMENTS를 읽는다. 필요한 분기만 실행한다.

## 기본: 다음 단계
기존 문서가 있으면 catalog·현재 spec·작업 상태를 읽는다. 환경 점검이 필요하면 edu-start, 만들 앱·MVP가 미확정이면 edu-interview를 안내한다. 없는 문서를 읽으려다 실패한 것을 앱 버그로 취급하지 않는다.
요청이 버그이면 edu-fix, 기대 동작 변경이면 edu-change로 연결한다. 잘못 선택한 명령도 의도에 맞게 안내하며 두 절차를 동시에 실행하지 않는다.
draft→edu-spec, specified→edu-mockup, designed→edu-plan, planned→edu-build, building→현재 작업 이어가기, blocked→강사 인계다.
ready면 validation의 수동 확인 상태를 확인하고 변경 파일·추천 커밋을 보여준다. 사용자 확인과 실제 git log의 커밋을 확인하면 done으로 기록한다. 완료 뒤 다음 현재 회차 spec을 안내한다. 미래 로드맵 전체를 자동 구현하지 않는다.

## roadmap: MVP 사용 후 전체 로드맵
MVP를 실제로 사용했는지와 불편한 점을 확인한다. 확정한 앱의 인터뷰와 보류 아이디어를 참고한다. HTML 편집기 예제를 선택했을 때만 .claude/edu-templates/feature-catalog.md의 수업 선택 목록을 읽는다.
.edu/roadmap.md에 전체 기능 묶음·의존성·이번 회차·후속 회차를 쓴다. mvp-roadmap은 최초 계획으로 보존한다. 기존 번호를 바꾸지 않는다. HTML 편집기 수업 회차는 003 실행 취소, 변경 시연, 004 배경색을 제안한다. 다른 앱은 해당 목적과 우선순위로 정한다. 전체 기능의 상세 spec을 한꺼번에 작성하지 않는다.

## backlog 내용: 새 아이디어
backlog의 다음 B번호를 부여해 날짜·아이디어·이유·연결 spec·후보 상태로 기록한다. 같은 아이디어가 있으면 보강한다. 코드·현재 spec·현재 상태는 바꾸지 않는다. 원래 작업을 계속할 수 있게 한 줄로 알린다.

## adopt B번호: 이번 회차로 채택
현재 회차의 기존 spec들이 완료됐는지 확인한다. 미완료이면 아이디어를 유지하고 완료 후 채택을 안내한다. 사용자가 명시적으로 우선순위를 바꾸면 그 변경을 기록한다.
기존 roadmap의 spec과 연결하거나 새 안정된 ID를 부여하고 backlog 상태를 채택으로 바꾼다. 바로 구현하지 않고 edu-spec→목업→plan→구현을 거친다. 완료 후 backlog에 연결 spec과 완료일을 기록한다.

## 보여줄 것
현재 기능·완료한 것·남은 확인·다음 명령을 최대 5줄로 보여준다. 사람이 할 판단을 기다리는 동안 자동으로 다음 단계를 진행하지 않는다.
