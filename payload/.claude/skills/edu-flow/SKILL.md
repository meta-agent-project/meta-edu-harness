# 환경과 진행 안내

$ARGUMENTS에 해당하는 분기만 실행한다. 알려진 사실과 선택은 다시 질문하지 않는다.

## start: 시작·환경 확인
CLAUDE.md와 공통 규칙, 기존 설치 기록을 확인한다. 제공 폴더를 다시 설치하지 않는다. 실제 Node.js·Git 버전과 npm run doctor를 확인하고 setup.md에 기록한다. 기존 프로젝트에서는 존재하는 명령만 실행한다. Claude 로그인·Code 로컬 세션·스킬 인식은 사람이 확인한 결과와 도구로 확인한 결과를 구분한다. 설치가 빠졌으면 주최 측에 알리고 전역 설정이나 원격 저장소를 자동 생성하지 않는다. 앱 목적이 미확정이면 edu-interview, 이미 확정됐으면 해당 단계로 연결한다.

## 기본: 다음 단계
catalog와 현재 spec의 실제 작업·검사 상태를 확인한다. draft→edu-spec, specified→필요한 edu-mockup 또는 생략 근거 후 edu-plan, designed→edu-plan, planned→edu-build, building→현재 작업, ready→edu-converge와 사람 확인, blocked→원인 해결·강사 인계다. 기대 동작 변경은 edu-change로 연결한다. 명세와 다른 실제 동작은 현재 개발 단계에서 재현하고 고친다.
완료 조건·정합성·사람 확인을 충족하고 커밋이 요청됐다면 대상 변경을 검토한다. catalog의 완료 상태를 포함해 기능 단위로 커밋하고 실제 git log를 확인한다. 실패하면 ready로 복원하고 커밋 실패를 보고한다. 미래 로드맵을 자동으로 끝까지 구현하지 않는다.

## roadmap: 큰 방향·사용자 테스트·본개발
처음에는 MVP와 본개발이라는 두 단계의 방향만 roadmap.md에 적고 MVP의 작업 순서는 mvp-roadmap.md에 둔다. MVP를 실제 사용한 후 feedback.md에 관찰한 동작, 불편, 추가·보완 후보를 기록한다. 사용자 선택으로 본개발의 우선순위·의존성·이번 회차 범위를 확정한다. HTML 편집기일 때만 feature-catalog.md를 참고한다. 4시간 공동 실습은 실행 취소 1회 하나, 강사 시연은 같은 spec의 10회 변경과 wiki다. 모든 기능의 상세 spec을 미리 쓰지 않는다.
미착수 항목의 확정된 변경·추가는 roadmap에 반영할 수 있다. 기존 식별자는 유지하고 순서만 조정한다. 이미 진행 중이거나 완료한 spec의 기대 동작 변경은 edu-change로 연결한다.

## backlog / adopt
채택 전 아이디어는 다음 B번호로 이유·연결 기능을 기록하고 현재 작업을 계속한다. 사용자가 채택하면 중복 spec을 만들지 않고 연결한다. 기본은 현재 회차를 마친 뒤 다음 범위에 넣는다. 사용자가 미착수 범위나 우선순위를 명시적으로 바꾸면 변경한 로드맵을 먼저 보여준다. 바로 구현하지 않고 spec부터 시작한다.

현재 기능·완료한 것·남은 확인·다음 단계만 최대 5줄로 보고한다. 이번 회차가 완료됐다면 edu-wiki와 프로젝트 보관을 안내한다.
