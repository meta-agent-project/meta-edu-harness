# 문서와 코드의 정합성 확인

1. 현재 spec의 AC, plan, 실제 변경 코드, validation, 해당 roadmap 항목만 읽는다. 문서가 있다고 구현된 것으로 보지 않는다.
2. AC별 실제 동작과 검사 근거, 선택한 화면과 구현 화면, roadmap 범위·상태를 대조한다. 실행 시점 이후 코드가 바뀌었다면 관련 검사를 다시 확인한다. 막 통과한 동일 검사를 이유 없이 반복하지 않는다.
3. 불일치를 명세 누락·구현 오류·낡은 문서·미실행 확인으로 구분한다. 승인된 현재 spec을 기준으로 고친다. 코드가 틀린데 spec을 코드에 맞춰 낮추지 않는다. 기대 자체를 바꿔야 하면 edu-change로 연결한다.
4. 작은 낡은 설명은 바로 정리한다. 구현 수정은 관련 실패 검사와 edu-build로 돌아간 뒤 회귀 검사를 확인한다. 무관한 리팩터링이나 전 문서 재작성을 하지 않는다.
5. validation.md의 정합성 항목에 확인 범위·불일치·조치·남은 확인만 기록한다. 미실행·불일치가 있으면 통과나 done으로 표시하지 않는다.
6. 모두 맞으면 ready와 사람 확인 항목·커밋 메시지를 보여주고 edu-flow의 완료 처리를 따른다. 사용자가 화면을 확인했고 커밋도 요청했다면 반복 승인 질문 없이 그 범위에서 진행한다.

보고: 일치한 범위 / 해결했거나 남은 불일치 / 커밋 가능 여부. 정합성 검사를 모든 버그가 없다는 보증으로 표현하지 않는다.
