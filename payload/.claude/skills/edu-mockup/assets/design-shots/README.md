# 디자인 few-shot 사용법

index.html을 브라우저에서 열어 요청→결과 화면 예시를 비교한다. 상단 도구 모음형 A, 간결한 작업실형 B, 캔버스 중심형 C에서 서로 다른 두 예시를 고른다. 주 기준과 보조 예시, 원하는 특징을 정한 뒤 생성된 프롬프트를 edu-mockup에 전달한다.

모델은 examples.json의 해당 두 항목과 선택된 HTML만 읽는다. 예시 경로가 설치 폴더와 다르면 현재 프로젝트의 실제 경로를 쓴다. HTML을 화면으로 볼 수 없는 도구에서는 배치·스타일 코드를 읽은 것과 실제 렌더링을 구분한다.

입력→출력 예시와 이번 요청을 구분한다. 결과 화면의 기능은 확정된 spec을 늘리는 근거가 아니다. 세 디자인 모두 같은 HTML 편집기 MVP의 동작을 배치한 정적 참고 화면이다. PowerPoint 등 특정 제품의 실제 화면을 복제한 자료가 아니다.

최종 산출물: .edu/specs/001/mockups/a.html, b.html, selected.html, design-choice.md. 주 기준·보조 예시의 ID/경로·차용/제외 특징·목업 선택 이유를 design-choice.md에 기록하고 spec과 plan에서 연결한다. 스펙 번호가 다르면 해당 번호를 사용한다.

3개 참고 디자인 / 모델이 만드는 목업 2안 / 후속 슬라이드 테마 4개는 각각 다르다. 이번에는 UI 디자인을 참고하며 PPTX 입출력 기능을 구현하지 않는다. 다른 앱이라면 해당 앱의 참고 자료를 우선하고 이 편집기 배치를 강요하지 않는다.
