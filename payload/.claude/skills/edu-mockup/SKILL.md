# 예시를 참고해 두 시안 비교

1. 현재 spec·기존 화면·기존 design-choice.md를 읽는다. 범위가 미확정이면 spec을 먼저 확정한다. 같은 선택을 다시 묻지 않는다.
2. 사용자가 제공한 디자인 자료가 있으면 우선한다. HTML 편집기를 처음 설계하면서 참고 자료가 없으면 이 스킬의 assets/design-shots/index.html을 실제 로컬 경로로 안내한다. 예시 A 상단 도구 모음형, B 간결한 작업실형, C 캔버스 중심형의 요청→결과 화면을 비교하고, 주 기준과 보조 예시 2개·차용할 특징을 고르게 한다. 다른 앱에는 편집기 예시를 강요하지 않는다. 후속 기능에서는 이미 선택된 화면을 재사용한다.
3. 선택된 두 예시의 examples.json 항목과 해당 HTML만 읽는다. 전체 예시나 외부 디자인을 반복 탐색하지 않는다. 요청→결과 예시와 이번 앱의 요청을 구분하고 배치·색·여백·도구 위치 중 무엇을 차용하고 제외할지 정리한다. 이미 프롬프트에 선택이 있으면 바로 적용한다. 브라우저를 사용할 수 없으면 코드에서 확인한 것과 실제 화면 확인을 구분한다.
4. .claude/edu-templates/design-choice.md를 참고해 .edu/specs/번호/mockups/design-choice.md에 예시 ID·실제 경로·차용/제외 특징을 기록한다. 이때 최종 목업 선택은 대기로 둔다. 디자인 참고만으로 spec 밖 기능을 늘리지 않는다. PPTX 입출력은 이번 HTML 편집기 MVP에 포함하지 않는다.
5. MVP는 화면 전체, 후속 기능은 달라지는 부분만 a.html·b.html 두 정적 시안으로 만든다. 같은 완료 조건을 유지하며 배치·사용 동선에 의미 있는 차이를 준다. 각 시안의 차용 근거를 짧게 설명한다. 참고 디자인 3종, 생성할 목업 2안, 후속 슬라이드 테마 4개를 구분한다. 실제 앱 기능은 아직 구현하지 않는다.
6. 열 수 있는 시안 경로와 차이를 보여 주고 사용자의 선택을 기다린다. 선택한 안을 selected.html로 복사하고 design-choice.md에 선택 이유를, spec에는 해당 기록의 링크를 남긴다. 이미 선택이 확정됐으면 다시 묻지 않는다. 미선택 상태에서 designed로 바꾸지 않는다.
7. 화면 변화가 없는 기능은 기존 디자인 선택을 유지하고 생략 이유를 적어 designed로 표시한다. 다음은 edu-plan이며 선택한 화면과 디자인 기록을 연결한다. 추가 아이디어는 backlog로 남긴다.
