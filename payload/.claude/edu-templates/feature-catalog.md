# 전체 기능 로드맵

사용자가 선택한 원래 기능 번호를 유지했다. 아래는 MVP 사용 후 작성할 전체 로드맵의 강사용 예시다. starter의 초기 로드맵은 MVP만 확정하고, 후속 spec 상세는 해당 기능을 시작할 때 만든다.

## 두 로드맵

- MVP 로드맵: SPEC-001의 8개 기능을 사용 가능한 한 묶음으로 만든다.
- 전체 로드맵: MVP 사용 후 불편과 우선순위를 반영해 아래 기능 묶음을 순서화한다.
- 기본 수업 회차: SPEC-001→SPEC-003→요구사항 변경 시연→시각적 wiki. 나머지는 다음 회차로 보존한다.
- 번호는 식별자다. 우선순위를 바꿔도 번호와 기존 spec 파일명을 바꾸지 않는다.

## 테마와 레이아웃

테마는 4개로 한다. 예시는 밝은 기본형, 어두운 발표형, 차분한 문서형, 선명한 세미나형이다. 이름과 색은 해당 spec·시안에서 선택한다. 테마 4종과 레이아웃 20종은 다른 개념이므로 별도로 유지한다. 기존 “테마 20페이지 전체 가져오기”는 선택한 테마의 전체 레이아웃 페이지 가져오기로 다룬다. 실제 페이지 구성과 공통화 방법은 SPEC-011에서 정한다.

## 권장 의존 순서

MVP→실행 취소→슬라이드 관리·배경→텍스트·콘텐츠→크기·회전·다중 선택→배치·그룹→레이어→테마→레이아웃·재사용→작업 화면→원본 보존·단축키·다시 실행.

순서 자체는 수강생이 바꿀 수 있다. 다중 선택 정렬은 다중 선택이 먼저 필요하고, 다시 실행은 실행 취소 모델의 영향을 받는다는 의존성을 설명한다. 로컬 JSON 프로젝트 보관은 “내 페이지” 등의 보존 범위를 정할 때 검토하며 외부 DB를 필수로 추가하지 않는다.

## backlog 예시

| ID | 아이디어 | 이유 | 상태 | 연결 |
|---|---|---|---|---|
| B001 | 슬라이드 배경색 변경 | 내 자료 분위기에 맞추기 | 후보 | 채택 시 SPEC-004 |
| B002 | 회전 각도 숫자 입력 | 정확히 15도로 돌리기 | 후보 | SPEC-007에서 상세화 |
| B003 | 단축키 직접 설정 | 자주 쓰는 편집을 빠르게 | 후보 | SPEC-014에서 상세화 |

이미 로드맵에 있는 기능에 대한 새 아이디어는 연결만 보강한다. 중복 spec을 만들지 않는다. 현재 회차를 마친 뒤 선택한 backlog를 spec으로 승격하고, 실제 검증 후 완료로 표시한다.
